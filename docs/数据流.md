# 数据流

> 一次问诊请求的完整数据流转（以"头痛三天"为例）

---

## 一、完整请求链路

```
① 请求进入
   用户 POST → {session_id, message: "头痛三天", user_token}

② 加载状态
   Redis 查询 → 命中返回 / 未命中查 MySQL → 回写 Redis

③ MCP 工具预检（collect）
   关键词检测：用户消息中是否有药品/文件/历史提及
   ├─ 无 → 跳过
   └─ 有 → MCP 工具调用 → 结果注入上下文

④ 症状提取（collect）
   请求 LLM：从用户输入中提取症状和病史
   LLM 返回：{"symptoms": ["头痛"], "history": [], "tool_calls": [...]}
   如有 tool_calls → 执行 MCP → 二次提取

⑤ 条件判断 A
   collected_symptoms = ["头痛"] → 1个 < 3个 → 追问
   ✓ 返回："您已提到：头痛。请再详细描述一下..."

⑥ 用户补充 → "还有发烧、恶心，能吃阿司匹林吗？"
   再次进入流程...
   collected_symptoms = ["头痛", "发烧", "恶心"] → 3个 ≥ 3个 → 继续

⑦ 知识检索（retrieve）
   ChromaDB 向量检索 → 返回 Top-10
   关键词重排序 → RRF 融合 → 输出 Top-5 医学文档
   返回：发热定义、头痛分类等文档内容

⑧ MCP 工具调用（analyze）
   检测到"阿司匹林" → get_drug_info 调用
   药品信息合并到 rag_context

⑨ 分析诊断（analyze）
   请求 LLM：症状 + 病史 + 医学知识 + 药品信息
   LLM 返回：诊断分析 + urgency: medium + 科室: 神经内科/感染科

⑩ 反思评审（reflect）
   请求 LLM 评审诊断质量（一致性/完整性/准确性）
   LLM 返回：评分 + 反馈 + 是否通过
   ├─ 通过 → 继续生成报告
   ├─ 不通过 & 轮次未用尽 → 回 analyze 精炼（带上反馈）
   └─ 不通过 & 轮次用尽 → 强制继续 + 报告追加人工复核声明

⑪ 报告生成（generate_report）
   请求 LLM：基于诊断分析生成结构化 Markdown 报告
   LLM 返回：完整报告（主诉、诊断分析、建议检查等）
   （若轮次用尽且质量不达标，报告开头加 ⚠️ 建议人工复核）

⑫ 持久化
   乐观锁保存状态 → MySQL upsert + Redis 更新
   保存消息记录 → MySQL messages 表

⑬ 返回
   {response: 报告, urgency_level, is_complete, session_id}
```

## 二、精炼循环示例

```
假设第一轮评分 2/5，未通过：

                   ┌──────────────────────────────────────┐
                   │  ⑨ analyze（初版分析）                │
                   │     round=0                          │
                   └──────────────┬───────────────────────┘
                                  │
                                  ▼
                   ┌──────────────────────────────────────┐
                   │  ⑩ reflect（评分 2/5，不达标）        │
                   │     feedback: "缺少对发热时间的描述"   │
                   └──────────────┬───────────────────────┘
                                  │ 不达标 & round(0) < max_rounds(2)
                                  ▼
                   ┌──────────────────────────────────────┐
                   │  ⑨ analyze（精炼 — 带上反馈）          │
                   │     输入初版分析 + reflect feedback   │
                   │     round=1                          │
                   └──────────────┬───────────────────────┘
                                  │
                                  ▼
                   ┌──────────────────────────────────────┐
                   │  ⑩ reflect（评分 4/5，达标）          │
                   └──────────────┬───────────────────────┘
                                  │ 通过
                                  ▼
                   ┌──────────────────────────────────────┐
                   │  ⑪ generate_report                   │
                   └──────────────────────────────────────┘
```

## 三、MCP 工具调用数据流

```
collect 节点内的 MCP 数据流：

  user_message = "我头痛，能吃阿司匹林和布洛芬吗？"
       │
       ├─→ _detect_and_call_tools()
       │       │
       │       ├─ 关键词匹配 → "阿司匹林", "布洛芬"
       │       ├─ MCP get_drug_info("阿司匹林") → 药品信息 JSON
       │       ├─ MCP get_drug_info("布洛芬")   → 药品信息 JSON
       │       ├─ MCP check_drug_interaction("阿司匹林", "布洛芬")
       │       │    → 严重相互作用：增加胃肠道出血风险
       │       │
       │       └─ 所有结果 → 注入 LLM 上下文
       │
       └─→ extract_symptom(context + MCP 结果)
               │
               └─→ LLM 返回：症状 + 药品分析

analyze 节点内的 MCP 数据流：

  symptoms = ["头痛", "发烧"]
       │
       ├─→ _detect_analyze_tool_needs()
       │       ├─ 扫描症状 → 发现药品提及
       │       └─ MCP get_drug_info → 药品信息
       │
       └─→ analyze_diagnosis(rag_context + MCP 结果)
```

## 四、多轮对话状态持久化

```
首次问诊：
  SessionService.load_state() → 无数据 → 返回 None
  ConsultationGraph.run() → 生成状态
  SessionService.save_state() → MySQL INSERT + Redis SET

后续问诊：
  SessionService.load_state() → Redis GET（命中）→ 返回累积状态
  ConsultationGraph.run(accumulated_state) → 继续问诊
  SessionService.save_state() → MySQL UPDATE（乐观锁 version+1）+ Redis SET

乐观锁机制：
  save_state 时校验 state_row.version == old_version
  不一致 → 抛出 VersionConflict → 调用方重试
```
