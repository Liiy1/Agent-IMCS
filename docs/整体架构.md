# 整体架构

> Agent-IMCS 智能医疗问诊系统四层架构

---

## 一、四层架构总览

```
┌────────────────────────────────────────────────────────────┐
│                    后端服务层                               │
│  FastAPI 路由 + SessionService + RedisCache                │
│  职责：请求入口、参数校验、会话状态加载/保存               │
│        并发控制（乐观锁）、缓存降级                         │
├────────────────────────────────────────────────────────────┤
│                    Agent协作层                              │
│  LangGraph 五节点状态机 + 反思闭环 + MCP 工具调用子步骤    │
│  职责：编排问诊流程、控制追问节奏                          │
│        收集→检索→分析→反思→报告 全链路调度                │
│        质量不达标时自动回 analyze 精炼                      │
│        LLM 按需调用 MCP 工具获取外部数据                   │
├────────────────────────────────────────────────────────────┤
│                     AI服务层                                │
│  LLMService + MedicalRAGRetriever + MCPClient              │
│  职责：LLM 统一调用（DeepSeek/OpenAI 切换）                │
│        JSON 响应清洗、向量检索 + 关键词重排序              │
│        jieba 中文分词、reflection 质量评审                 │
│        MCP 工具注册与调用（药品/病历/文件/排班）           │
├────────────────────────────────────────────────────────────┤
│                    数据存储层                               │
│  MySQL + Redis + ChromaDB + SQLite(药品库)                 │
│  职责：关系型持久化、热缓存加速、知识向量检索              │
│  MySQL: 会话、消息、状态（带乐观锁 version）               │
│  Redis: 会话状态缓存（TTL=1800s，可降级）                  │
│  ChromaDB: 医学知识库（bge-small-zh 嵌入）                 │
│  SQLite: MCP 药品数据库（50 种常用药品）                   │
└────────────────────────────────────────────────────────────┘
```

## 二、各层职责详解

### 1. 后端服务层

| 组件 | 职责 |
|------|------|
| `FastAPI` | HTTP 路由、参数校验、CORS、生命周期管理 |
| `SessionService` | 会话状态 Redis → MySQL 二级读写、乐观锁、消息持久化 |
| `RedisCache` | 异步 Redis 封装、连接失败优雅降级（MySQL-only） |
| `config.py` | pydantic-settings 配置加载（含 MCP、反思等开关） |

### 2. Agent 协作层

| 节点 | 职责 | 相关文件 |
|------|------|----------|
| `collect` | 提取症状/病史、MCP 工具预检 + LLM 工具决策、追问判断 | `nodes.py` |
| `retrieve` | RAG 混合检索医学知识库 | `nodes.py` → `retriever.py` |
| `analyze` | LLM 诊断分析、MCP 药品查询、紧急分级、科室推荐 | `nodes.py` |
| `reflect` | LLM-as-Judge 质量评审（1-5 分）、精炼决策 | `nodes.py` |
| `generate_report` | LLM 结构化 Markdown 报告生成 | `nodes.py` |

条件边：
- `should_continue`：collect → ask(END) 或 retrieve
- `should_reflect`：reflect → refine(回 analyze) 或 generate_report

### 3. AI 服务层

| 组件 | 职责 |
|------|------|
| `LLMService` | 统一 LLM 调用（DeepSeek/OpenAI）、JSON 清洗、延迟追踪 |
| `MedicalRAGRetriever` | ChromaDB 向量检索 + jieba 关键词 + RRF 融合 |
| `MCPClient` | 工具注册、本地/远程双模式、LLM 驱动的工具调用 |

### 4. 数据存储层

| 数据库 | 用途 | 备注 |
|--------|------|------|
| MySQL 8.4 | 会话、消息、状态持久化 | asyncmy 异步驱动，乐观锁 |
| Redis 8 | 会话状态缓存 | TTL=1800s，可优雅降级 |
| ChromaDB | 医学知识向量库 | bge-small-zh 嵌入，8 篇种子文档 |
| SQLite | MCP 药品药典 | 50 种常用药品 + 相互作用数据 |

## 三、请求全链路时序

```
用户 ──→ POST /consult ──→ Router
                                │
                                ├─ SessionService.load_state()
                                │    ├─ Redis.get() ── 命中? ──→ 直接返回
                                │    └─ MySQL.query() ──→ 回写 Redis
                                │
                                ├─ Graph.run(accumulated_state)
                                │    ├─ collect → MCP 预检 + LLM 提取 + MCP 工具决策
                                │    ├─ (不足 → 追问，结束本轮)
                                │    ├─ (充足 → 继续)
                                │    ├─ retrieve → RAG 检索 ChromaDB
                                │    ├─ analyze → MCP 药品检测 + LLM 诊断分析
                                │    ├─ reflect → LLM 评审质量（评分 1-5）
                                │    │    ├─ (达标 → 继续)
                                │    │    ├─ (不达标 & 轮次未用尽 → 回 analyze 精炼)
                                │    │    └─ (不达标 & 轮次用尽 → 强制出报告 + 人工复核声明)
                                │    └─ generate_report → LLM 写报告
                                │
                                ├─ SessionService.save_state()
                                │    ├─ 乐观锁 version 校验
                                │    ├─ MySQL.upsert()
                                │    └─ Redis.set()
                                │
                                └─ 返回 ConsultResponse ──→ 用户
```

## 五、配置项一览

```python
# config.py 完整配置项

# LLM 提供商
LLM_PROVIDER               = "deepseek"      # deepseek 或 openai
DEEPSEEK_API_KEY           = "sk-xxx"        # DeepSeek 密钥
DEEPSEEK_MODEL             = "deepseek-chat"
OPENAI_API_KEY             = "sk-xxx"        # OpenAI 密钥
OPENAI_MODEL               = "gpt-4-turbo-preview"

# 数据库
DATABASE_URL               = "mysql://user:pass@localhost:3306/medical_consult"
REDIS_URL                  = "redis://localhost:6379/0"

# 向量库
VECTOR_DB_PATH             = "./data/chroma"

# MCP 工具层
MCP_ENABLED                = True            # MCP 总开关
MCP_SERVER_URL             = "http://localhost:8001"  # 远程模式地址（预留）

# 反思机制
REFLECTION_ENABLED          = True           # 总开关
REFLECTION_MAX_ROUNDS      = 2              # 最大分析轮次（含初版）
REFLECTION_PASS_THRESHOLD  = 3              # 最低通过分数（1-5 评分制）

# 缓存
REDIS_CACHE_TTL            = 1800           # 会话状态缓存 TTL（秒）
```
